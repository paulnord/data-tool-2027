# Example datasets

**Data… → Examples** has two visible groups: **Synthetic data**, with 14 CSV files, and **Published studies**, with 15 choices. Fourteen published studies open configured `.trksess` sessions; the photon-index/temperature study opens a CSV. Status badges distinguish **Reproduced**, **Close**, **Comparison**, **Not reproduced** and **Unsupported** studies. These are publication comparisons, not a blanket claim that every published analysis has been reproduced. The groups remain visible while their example lists scroll. Startup remains empty, and choosing an example follows the normal import/review path.

Use **Data… → Load file…** for additional ordinary files. The desktop file chooser initially opens the bundled Examples directory, which also contains prepared synthetic `.trksess` analyses. The same files live in `examples/data/` in the checkout. CSVs can be shared, pasted or used by another analysis program. They contain column headings, explicit units where supplied and observations. Generated CSVs identify their synthetic origin; they do not contain hidden fit settings or executable generators.

Additional synthetic sessions for logarithmic, reciprocal, cubic and quartic fits are available through Load file. Collision and multi-interval examples contain source data, not saved workspace configurations; see [collision scope](collision-draft.md) and [multi-interval scope](multi-interval.md).

`MillikanData.csv` contains columns `t`, `mass_B`, `mass_A`, and `mass_C`, with some missing observations. It can be used to inspect several measured columns and choose one as Y for drift-interval line fits. Time is in seconds and all three measurement columns are in millimeters, as confirmed by the instructor. Units are declared in the CSV headings; numerical observations and missing values are unchanged.

Loading a CSV does not automatically fit, assert statistical assumptions or assign an uncertainty column. Review the source table and units, then choose X, Y and optional Y uncertainty beside the model in the Analysis panel. For the unequal-uncertainty example, assign the standard-deviation column to Y uncertainty there. Use **Export CSV…** for the table and **Save session** for a reproducible analysis with settings.

Prepared sessions include a selected model, constraints and documented noise provenance. Their observations and settings remain in normal `.trksess` files; no sample is loaded implicitly on startup.

## Provenance and numerical validation

The generated datasets are synthetic. `MillikanData.csv` is an instructor-supplied file, with original numerical observations preserved and instructor-confirmed units added to the headings. The first two are hand-authored examples: constant-speed data are near `position = 0.35 + 1.4*time`; spring data are near `force = 0.1 + 25*extension`. Their small deviations are illustrative and do not establish a Gaussian noise model.

The original CSVs retain observations from the corresponding prepared sessions (except the updated exponential example described below): ball toss uses `height = 2 + 10*time - 4.905*time²`; exponential uses `signal = 0.5 + 3*exp(-0.7*x)`; oscillation uses `y = 1 + 2*sin(2*pi*time/3) + 0.75*cos(2*pi*time/3)`; unequal uncertainties use `y = 1 + 2*x` with `sigma = 0.04 + 0.18*x`. Their original seeds and generation assumptions are in the paired session provenance. Finite noisy samples need not recover the generating coefficients exactly.

Tests read these same static CSV files through production parsing and table validation, check precision and session round trips, and run descriptive fits. The browser suite verifies ordinary file opening and reopening. Internal Monte Carlo generators and scientific acceptance tests remain under `tests/`; they are not exposed as production test controls or included in the application module graph.

## Further nonlinear examples

The same directory now also contains `power-law-free.csv`, `gaussian.csv`, `damped-sine.csv` and `lorentzian.csv`; `exponential-decay.csv` is updated for the fitted-decay-time example. The corresponding models support starting values and fixed or free shape parameters. Peak widths are shape parameters, not measurement uncertainties. See [model equations and diagnostics](nonlinear-fits.md).

These five nonlinear datasets were generated by `scripts/generate-nonlinear-reference.py` with NumPy PCG64 seeds 93000–93004. Their generating parameters, exact observations and independent reference fits are recorded in `tests/fit/nonlinear-reference.json`. The updated exponential example uses `signal = 0.4 + 3*exp(-time/2.2)`; it is separate from the older prepared supplied-rate exponential session.

## Published studies

The `published/` directory contains 15 studies with a CSV and [individual documentation linked from the comparison index](../examples/data/published/README.md). Fourteen also have a configured session. The [pulsar photon-index/temperature study](../examples/data/published/pulsar-photon-index-vs-temperature.md) remains a CSV because its publication used orthogonal-distance regression; preserving the X-error column does not make those errors part of Data Tool's Y-error fit. The pages record independently checked calculations and explicitly labeled publication comparisons.

The menu labels identify damped oscillations, interval counts, the measured pulsar or pulsar-wind-nebula luminosity relation, and the smoothed supercooled-water values where those distinctions matter. The badges summarize the comparison outcome, while the accompanying page remains the authority for the exact model, rows, uncertainty convention and caveats. In particular, **Not reproduced** means that the documented Data Tool and independent SciPy calculations agree with each other but not with every reported publication value; it does not assert that the publication is wrong. **Unsupported** identifies a published objective, such as orthogonal-distance regression, that Data Tool does not implement.

The Ba-137m file contains one trace rather than the publication's five-run ensemble, and the supercooled-water file contains rounded smoothed values rather than the original measurements. They remain useful provenance studies, but they are not validation benchmarks for the corresponding ensemble uncertainty or raw-data statistic.

### Five-stage reproducibility sequence

1. **Reproduce a benchmark — BESIII.** Record the selected columns, equation, uncertainties, free parameters and degrees of freedom, then compare the fitted parameters, standard errors and chi-square with the publication.
2. **Change an uncertainty convention — ASASSN-14li radio.** Compare errors that retain the supplied uncertainty scale with errors multiplied by `sqrt(reduced chi-square)`. Explain why this changes reported standard errors without changing the best-fit parameters.
3. **Change the fit domain — ion chamber or DyFeO3.** Vary the selected rows or lower time limit. Track a fitted parameter against that choice and distinguish the statistic on fitted rows from a separate evaluation on all rows.
4. **Recognize an unsupported objective — photon index versus temperature.** Explain why a Y-error fit cannot reproduce orthogonal-distance regression when X also has uncertainty. Export the data for comparison with an ODR-capable program if desired.
5. **Investigate non-reproduction — ASASSN-14li X-ray.** Confirm that Data Tool and an independent calculation agree for the 95 printed rows, compare the paper's stated monitoring start with its first table entry, and identify the three earlier Swift observations. Explain why values from a newer reduction can diagnose the discrepancy but should not be silently merged into the published table.

### Learning outcomes

Students should be able to:

- distinguish software verification from reproduction of a publication;
- document the data, units, model, fit window, fixed parameters, uncertainty model and definition of the fit statistic;
- distinguish supplied measurement uncertainty, scatter estimated from residuals and a common systematic uncertainty;
- explain how fit windows and evaluation rows affect parameters and goodness-of-fit statistics;
- recognize when Y-weighted least squares is not the published objective, including X uncertainty, correlated errors or count-data likelihoods; and
- treat a well-checked non-reproduction as a scientific result to investigate rather than evidence by itself that either implementation is wrong.

Any future switch from a CSV menu entry to a prepared session should preserve the intended observations and document its model and uncertainty settings. In particular, the current exponential-decay CSV and older supplied-rate exponential session are different datasets, as described above. Newly supplied, unpublished measurements should not be described as a published study merely to fit an existing group.
